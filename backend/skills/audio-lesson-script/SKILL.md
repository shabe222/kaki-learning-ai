# 音频课讲稿改写法

## 听觉适配规则

1. 听众看不见代码和列表：代码示例改成语音描述（「这个函数先定义了一个计数器……」），
   列表改成「第一……第二……」。
2. 全文口语化但不过度：允许「你」「咱们」，禁止网络梗和感叹词堆砌。
3. 结构：开场 30 秒内说清这一课解决什么问题；主体按「规则 → 听觉化例子 → 常见误解」推进；
   结尾用 3 个自问自答的检索问题收束（问题后停半句，然后给答案）。
4. 每段一个语义单元，80-150 字；段落之间不依赖视觉衔接（不要「如上图」「这一行」）。
5. 术语首次出现时给一句白话解释，之后再直接用术语。
6. 内容只来自源材料；源材料没有的例子不发明。总时长目标 3-5 分钟（约 900-1500 字）。

## 输出格式

只输出 JSON：{"title": "...", "segments": [{"heading": "...", "speech": "..."}]}。
speech 是纯口播文本：无 Markdown、无围栏代码、无序号符号（「第一」用汉字）。
不要输出 JSON 之外的任何文字。
