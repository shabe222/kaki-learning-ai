# PPT / 互动课堂生成法

## 图文结合（硬规则）

1. 除封面外，每个内容页输出 illustration 字段：一个 30 字以内、可直接画出来的教学画面
   （具体主体 + 空间关系，例如「水杯中的筷子向上弯折，水面处错开」），供配图管线出图。
2. illustration 描述单一教学结构，与该页论点直接对应；不写抽象概念词（如「重要性」「流程图」），
   只写看得见的画面。
3. 无合适画面的页（如纯 quiz 判定页）illustration 写 ""，页面保持文字形态，不硬凑。

## 页面规则

1. 一页只承载一个论点；标题写判断句（「X 决定了 Y」），不写名词短语目录。
2. 页面正文 ≤ 5 条 bullet，每条 ≤ 20 字；细节全部移入 narration 旁白。
3. narration 是讲述人对着这一页会说的话（口语、可直接朗读），不是页面文字的复读。
4. 代码页代码 ≤ 12 行，配一行「看哪一行」的指点。
5. 互动课堂的提问页给期望答案与判定标准；选择题干扰项来自真实误区。
6. 生成主题必须服从调用方给定的主题与学习阶段，页数服从请求参数。

## 视觉编排（不是模板）

1. 每页先判断这页的视觉论点，再决定图与字的关系。`design.composition` 写出该页最适合的构图理由；不要把所有页面做成标题加项目符号加配图。
2. `design.image_position` 只能是 `right` / `left` / `background` / `full_bleed` / `inline` / `none`，按知识关系选择：对照适合左右并置，过程适合主画面，定义或代码可克制地不用图。
3. `design.density` 只能是 `airy` / `balanced` / `dense`。只有比较、代码或数据页可以 dense；初学概念页优先 airy，让图承担理解而不是装饰。
4. `design.emphasis` 是本页应被第一眼看见的一句话或关系；它必须来自本页论点，不得写通用设计词。
5. 主题只决定色彩、材质和氛围，不决定构图、内容顺序、插图题材或学习例子。不同主题下同一学习内容仍应保留最适合该内容的视觉叙事。

## 输出契约

严格输出调用方要求的 JSON slides 结构（title/subtitle/body/items/code/narration/illustration/design
等字段按现有 schema），不新增字段、不输出 JSON 之外的内容。修改模式只改指令点名的页面。
